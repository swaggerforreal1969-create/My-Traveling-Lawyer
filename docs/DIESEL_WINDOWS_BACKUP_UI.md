# Windows fictional backup button — customer outcome
New Windows startup control **Back Up Practice Case** uses existing authorized `backup_fictional_pilot`. It prompts for a fictional existing case, a fresh unused destination, and a masked owner code. Cancellation has no write; an already-existing or linked backup path is denied before asking for a code. The underlying existing service verifies ownership of every matter, complete audit chain, pending write fence, credential exclusion and snapshot integrity. On denied or uncertain output the GUI does not claim success. Successful output explicitly warns the backup is **not encrypted** and is forbidden for client data. This is a fictional-only development feature, **not a production-ready recovery solution**. Restore remains available through existing separate implementation and requires new credentials; it is not yet exposed in this startup GUI.
